# Architecture

A New Year ritual website: people write what they want to leave in the old year, pay a small amount, and watch their paper burn in a shared digital fire (on the site and on a YouTube live stream). Optional: a wish for the next year, kept and opened live next New Year's Eve.

The brand name is **not final**. Never hard-code a brand name or domain: read it from `site/config/site.json` (`brand.*`, `domain`).

## Stack

| Part | Choice | Why |
|---|---|---|
| Frontend | Static multi-page site generated by `site/build.py` (Jinja2 + Markdown) into `public/` | Fast, cacheable, no server to break, SEO-friendly, testable locally |
| Animation | three.js r128 + GSAP 3.12.5 (+ ScrollTrigger), self-hosted in `site/assets/vendor/` | No third-party CDN at runtime |
| Hosting | Vercel (static output `public/`, headers and rewrites in `vercel.json`) | |
| Database | Supabase Postgres (project ref `maqcaowpfhmqcavboszy`, eu-central-1) | |
| Server logic | Supabase Edge Functions (Deno, TypeScript) in `supabase/functions/` | Payment callbacks and order creation never run in the browser |
| Payments | Provider adapters: `disabled` (default, "coming soon"), `mock` (test only), `ameria` (Ameriabank vPOS), `idram` | Bank not chosen yet |

Languages: Armenian (`hy`, default, at `/`), English (`/en/`), Russian (`/ru/`).

## Money rules

- Every price is an integer in AMD. Prices live in `site/config/site.json` (frontend display) **and** in the `products` table (source of truth for charging). The server never trusts a price from the browser.
- **20% of every paid amount** goes to the New Year gift fund for children in Armenian orphanages. It is recorded per payment in `gift_ledger` at the moment the payment is confirmed, rounded down to whole AMD.
- We are a for-profit company and say so. The 20% is a choice we made, not the business model.

## Security rules (non-negotiable)

1. An order becomes `paid` **only** inside the database function `confirm_payment(...)`, called by an Edge Function after it verified the payment with the bank server-to-server (or with the provider's signature). The browser can never mark anything paid.
2. `confirm_payment` is idempotent: the same provider payment can't be counted twice, and the amount must equal the order amount.
3. All tables have RLS enabled with **no** policies for `anon`/`authenticated`. The browser reads data only through `SECURITY DEFINER` RPCs that return safe, public fields, or through Edge Functions.
4. Order codes are random, unguessable (16 chars, base32 lowercase without ambiguous letters). The code is the capability to view one's own order.
5. Papers are moderated before they can appear publicly. Text is shown on the public fire only if the buyer allowed it **and** moderation status is `approved`.
6. Rate limits per IP hash (salted SHA-256, never the raw IP) for order creation and waitlist.
7. Secrets only in Supabase function secrets / Vercel env, never in the repo.

## Database (schema `public`)

- `products(code text pk, price_amd int, active bool, sort int)` — codes: `burn`, `burn_wish`, `gift`, `midnight`.
- `orders`:
  `id bigint identity pk`, `code text unique`, `product text fk`, `amount_amd int`, `status text` (`awaiting_launch` | `pending` | `paid` | `failed` | `cancelled` | `refunded`),
  `lang text`, `email text null`, `text text` (≤120), `wish_text text null` (≤200), `recipient_name text null` (≤40),
  `show_on_stream bool`, `moderation text` (`pending` | `approved` | `hidden` | `rejected`), `moderation_reason text null`,
  `burn_number int unique null` (assigned at payment, sequential), `provider text null`, `provider_payment_id text null unique`,
  `provider_order_num bigint unique` (numeric id some banks require), `ip_hash text`, `created_at`, `paid_at`, `streamed_at`, `updated_at`.
- `gift_ledger(id, order_id fk unique, amount_amd int, created_at)` — 20% per paid order.
- `waitlist(id, email unique (citext or lower-unique), lang, created_at, ip_hash)`.
- `rate_limits(key text, window_start timestamptz, count int, pk(key, window_start))`.
- `payment_events(id, provider, kind, order_code, payload jsonb, created_at)` — raw audit of every callback.
- `burn_number_seq` sequence.

### RPCs callable by the browser (anon), all `SECURITY DEFINER`, `set search_path = public`

- `get_public_stats()` → `{ papers_burned, gift_fund_amd, wishes_kept, waitlist_count, updated_at }`
- `get_fire_feed(after_number int default 0, max_rows int default 50)` → rows `{ burn_number, text_public (null unless show_on_stream and approved), paid_at, product }` ordered by `burn_number`, `max_rows` capped at 100.

### Internal functions (service role only)

- `confirm_payment(p_code text, p_provider text, p_payment_id text, p_amount int)` → `{ ok, burn_number, already }`.
- `check_rate_limit(p_key text, p_limit int, p_window_seconds int)` → boolean.

## Edge Functions (base `https://<ref>.supabase.co/functions/v1/`)

All responses are JSON with CORS for the site origins (`ALLOWED_ORIGINS` secret, comma-separated; also allow `http://localhost:*` when `ALLOW_LOCALHOST=1`).
Error shape: `{ "error": { "code": "TEXT_TOO_LONG", "message": "..." } }` with a 4xx status.

### `POST create-order` (verify_jwt false; checks `apikey` header equals anon key is not required)

Request:
```json
{ "product": "burn", "text": "...", "wish_text": null, "recipient_name": null,
  "email": "optional@x.am", "lang": "hy", "show_on_stream": true, "consent": true }
```
Rules: `consent` must be true; `text` 1–120 chars after trim and whitespace collapse; `wish_text` required for `burn_wish` and `midnight` (1–200), forbidden otherwise; `recipient_name` required for `gift` (1–40); email optional but must be valid if present (required when payments are disabled, so we can send the link at launch).
Moderation: blocklist hit → `400 TEXT_REJECTED`; likely personal names/phone numbers/links → order allowed but `moderation='hidden'` (never shown publicly); otherwise `pending`.
Rate limit: 8 orders per IP hash per 10 minutes → `429 RATE_LIMITED`.

Response:
```json
{ "code": "k7m2...", "amount_amd": 500, "status": "pending",
  "payment": { "mode": "redirect", "url": "https://bank/..." } }
```
`payment.mode` is one of `redirect` (go to `url`), `mock` (go to `url`, test only), `form` (Idram: build a `<form method="POST" action="{action}">` with one hidden input per entry of `fields` and submit it: `{ "mode": "form", "action": "https://...", "method": "POST", "fields": { "EDP_...": "..." } }`), `disabled` (status is `awaiting_launch`; we saved the paper and will email a payment link when payments open).
Moderation at creation: with `AUTO_APPROVE=1` (default) a text the automatic checks found nothing in is stored as `approved`; otherwise `pending`.

### `GET order-status?code=...`

Returns the buyer's own order: `{ code, status, product, amount_amd, burn_number, text, has_wish, recipient_name, created_at, paid_at, gift_share_amd }`. The wish itself is never returned (order links get shared); `has_wish` is a boolean. `gift_share_amd` is the gift_ledger amount once paid, else the floor(20%) the order will contribute. 404 if unknown.

### `POST start-payment`

`{ "code": "...", "lang": "hy" }` starts (or restarts) payment for an existing order in `awaiting_launch`, `pending` or `failed` (launch emails; someone else paying from the order link). Disabled provider: `{ code, status, payment: { mode: "disabled" } }`, nothing changes. Otherwise the order becomes `pending` and the response is `{ code, status, payment }` with the same `payment` shapes as create-order. 404 `NOT_FOUND`, 409 `ALREADY_PAID` / `ORDER_NOT_PAYABLE`. Rate limit 8 per IP hash per 10 minutes.

### Payment provider endpoints

- `GET/POST pay-return-ameria` — Ameriabank BackURL. Reads `orderID`/`paymentID`, calls `GetPaymentDetails` server-to-server, checks `ResponseCode == "00"` and amount, then `confirm_payment`, then 302 to the order page: `${SITE_URL}/p/{code}` for hy (root) and `${SITE_URL}/{en|ru}/p/{code}` otherwise (vercel.json must rewrite `/p/:code` to the static `/p/?c=:code` page).
- `POST pay-callback-idram` — Idram EDP precheck + result callback with checksum verification; answers `OK`.
- `GET pay-mock?code=...` — only when `PAYMENT_PROVIDER=mock`; confirms and redirects. Returns 404 otherwise.

### `POST join-waitlist`

`{ "email": "...", "lang": "hy" }` → `{ "ok": true }`. Rate limit 5 per IP hash per 10 minutes.

### `POST admin` (for `/admin/`)

Header `x-admin-token` must equal secret `ADMIN_TOKEN` (≥ 32 chars, else always 401). 10 failed attempts per IP hash per 10 minutes → 429. Body `{ "action": ... }`:
`stats` → `{ orders_by_status, revenue_amd, gift_fund_amd, waitlist_count, papers_burned, pending_moderation }`;
`list_orders` `{ status?, moderation?, q?, limit ≤ 200, before_id? }` → `{ orders: [...] }` (newest first);
`moderate` `{ code, moderation: approved|hidden|rejected, reason? }`;
`mark_refunded` `{ code }` (paid → refunded, removes its gift_ledger row, audit row in payment_events);
`waitlist_csv` → `{ csv }`; `awaiting_launch_csv` → `{ csv }` with email, lang, code, product, amount_amd, link, created_at.

## Function secrets

`PAYMENT_PROVIDER` (disabled|mock|ameria|idram), `SITE_URL`, `ALLOWED_ORIGINS`, `IP_HASH_SALT`,
`AMERIA_CLIENT_ID`, `AMERIA_USERNAME`, `AMERIA_PASSWORD`, `AMERIA_API_BASE` (test: `https://servicestest.ameriabank.am/VPOS`),
`IDRAM_ACCOUNT_ID`, `IDRAM_SECRET_KEY` (`IDRAM_ACTION_URL` optional), `ALLOW_LOCALHOST`, `AUTO_APPROVE` (default 1), `ADMIN_TOKEN`. `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` are provided by the platform. Details: `docs/BACKEND.md`.
